Control de acceso y contraseñas

Seguridad lógica: permisos, listas de control de acceso (ACL) y políticas de contraseñas.

¿Qué es la seguridad lógica?

La seguridad lógica agrupa las barreras y procedimientos que protegen los datos y el software que los procesa, controlando quién puede acceder a ellos, tanto si están almacenados como si se están transmitiendo.

Su principio básico es: todo lo que no esté permitido debe estar prohibido. El control de acceso se apoya en dos procesos: la identificación (el usuario se da a conocer) y la autenticación (el sistema verifica esa identidad).

Permisos en Linux ACL Contraseñas

Permisos tradicionales en GNU/Linux

Usuarios, grupos y permisos

En Linux cada archivo pertenece a un usuario propietario y a un grupo propietario. Los permisos se asignan a tres categorías: usuario (u), grupo (g) y otros (o), y pueden ser lectura (r), escritura (w) y ejecución (x). 

$ ls -l
-rw-rw-r-- 1 profesor profesor 171 oct 3 2016 Makefile
-rw-r----- 1 conta01  conta01   58 sep 30 2016 README

El primer carácter indica el tipo (- archivo, d directorio, l enlace simbólico) y los nueve siguientes son los permisos de u, g y o.

ComandoFunción
chmod 640 ficheroAsigna permisos en octal (equivale a u=rw,g=r,o=).
chmod g+w ficheroAñade o quita permisos con notación simbólica.
chgrp grupo ficheroCambia el grupo propietario.
chown usuario:grupo ficheroCambia el propietario (solo root).
Limitación

Cuando usuario-grupo-otros no basta

Imagina que conta01.txt debe ser de lectura y escritura para conta02 e info01, y solo de lectura para info02. Con permisos clásicos habría que crear un grupo nuevo, añadir usuarios, cambiar el grupo del archivo y, para info02, dar lectura a "otros" (chmod o+r).

Agujero de seguridad: dar lectura a "otros" permite leer el archivo a todos los usuarios del sistema, no solo a info02. El sistema clásico no tiene suficiente granularidad.

Listas de control de acceso (ACL)

¿Qué son?

Las ACL amplían el sistema tradicional y permiten asignar permisos a usuarios o grupos concretos. Cada entrada indica un sujeto (usuario o grupo) y las operaciones que se le permiten.

Ejemplo: un fichero con la ACL (David: leer y escribir; Ángela: leer) permite a David modificarlo, mientras que Ángela solo puede consultarlo.

Buena práctica: usar los permisos tradicionales siempre que sean suficientes y recurrir a las ACL cuando se necesiten permisos más específicos.

Requisitos

El sistema de archivos debe tener las ACL habilitadas (ext4 y Btrfs las traen activadas por defecto) y el paquete acl instalado. 

dpkg -s acl                 # comprobar si está instalado
sudo apt-get install acl    # instalarlo si falta
sudo tune2fs -l /dev/vda2 | grep "Default mount options"

Herramientas: setfacl y getfacl

  • setfacl: asigna, modifica o elimina ACL.
  • getfacl: muestra los permisos tradicionales y las ACL.

Sintaxis para añadir o modificar una entrada:

setfacl -m tipo:identificador:permisos fichero_o_directorio
  • tipo: u (usuario), g (grupo), o (otros), m (máscara).
  • identificador: nombre del usuario o grupo.
  • permisos: r, w, x o combinaciones.
setfacl -m u:ana:rw documento.txt        # usuario
setfacl -m g:profesores:rwx directorio   # grupo
getfacl documento.txt                    # consultar
OpciónDescripción
-mAñade o modifica una entrada.
-xElimina una entrada concreta (setfacl -x u:jon fichero).
-bBorra todas las ACL y deja solo los permisos básicos UGO.
-RAplica los cambios de forma recursiva.
-dDefine la ACL predeterminada (solo en directorios).
-kBorra los permisos por defecto.

Es conveniente comprobar los permisos existentes con getfacl antes de ejecutar setfacl.

Tipos de entrada en una ACL

EntradaFormato
Propietario (owner)user::rwx
Usuario nombradouser:nombre:rwx
Grupo propietariogroup::rwx
Grupo nombradogroup:nombre:rwx
Máscara (mask)mask::rwx

La máscara (mask)

La máscara fija el máximo de permisos efectivos del grupo propietario y de los usuarios y grupos nombrados. No limita al propietario ni a "otros". 

user:info01:rwx
mask::rw-          → permisos efectivos de info01: rw-

Al añadir una entrada, setfacl suele recalcular la máscara automáticamente. Puede fijarse a mano con setfacl -m m:rw fichero.

Ejemplo práctico 1

Usuarios con permisos distintos sobre un fichero

El usuario crea fichero.txt y se quiere que: info01 solo lea, info02 lea y escriba, conta02 solo lea y conta01 no pueda hacer nada. 

touch fichero.txt
chmod a-rwx fichero.txt                 # quitar permisos básicos
setfacl -b fichero.txt                  # quitar ACL previas
setfacl -m u:info01:r  fichero.txt
setfacl -m u:info02:rw fichero.txt
setfacl -m u:conta02:r fichero.txt
getfacl fichero.txt
# file: fichero.txt
# owner: usuario
# group: usuario
user::---
user:info01:r--
user:info02:rw-
user:conta02:r--
group::---
mask::rw-
other::---

conta01 no necesita ninguna regla: al no coincidir con ninguna entrada cae en "otros", que no tiene permisos.

Ejemplo práctico 2

Efecto de la máscara

touch documento.txt
setfacl -m u:jon:rw documento.txt
setfacl -m u:ana:r  documento.txt
setfacl -m m:r      documento.txt
getfacl documento.txt
user::rw-
user:jon:rw-       #effective:r--
user:ana:r--
group::r--
mask::r--
other::r--

Aunque a jon se le dio rw, la máscara solo permite r, así que únicamente puede leer. Para eliminar su regla: setfacl -x u:jon documento.txt; para borrar todas las ACL: setfacl -b documento.txt.

Ejemplo práctico 3

ACL predeterminada en un directorio

setfacl -d -m u::rw proiektu_dir/
getfacl proiektu_dir/

Con -d se define una ACL default: no cambia los permisos del directorio, sino los que heredarán los ficheros y subdirectorios nuevos creados dentro. Solo se puede aplicar a directorios.

Políticas de contraseñas

Autenticación: ¿cómo demuestro quién soy?

Un usuario se autentica con un identificador y uno o más elementos de verificación:

MétodoEjemplo
Identificador y contraseñaAcceder a Moodle con usuario y clave.
Contraseña OTP (un solo uso)Código temporal en el móvil para confirmar en la banca online.
Certificado PKI en tarjeta o token USBTarjeta criptográfica con certificado digital y PIN.
BiometríaHuella dactilar o reconocimiento facial.
Sin acto (RFID)Tarjeta que abre una puerta al acercarla.

Todos responden a la misma pregunta y se resumen en tres tipos de factor: algo que sabes (contraseña), algo que tienes (tarjeta, token, móvil) o algo que eres (huella, cara).

Requisitos de una política de contraseñas

La contraseña debe ser compleja (robusta) y secreta. Una política adecuada establece:

  • Tamaño mínimo suficiente.
  • Caducidad: obligar a cambiarla periódicamente.
  • Número de intentos limitado antes de bloquear.
  • Histórico que impida repetir contraseñas anteriores.
  • Calidad y robustez comprobadas por el sistema.
  • Formación de los usuarios sobre cómo protegerlas.

Una contraseña buena cumple:

  • Mezcla de mayúsculas, minúsculas, números y símbolos.
  • Al menos 8 caracteres; lo recomendable es 12 o más.
  • No es una fecha ni un nombre propio, ni tiene relación con el usuario.
  • No aparece en ningún diccionario.
Contraseñas débiles: palabras de diccionario, secuencias simples (123456), pequeñas variaciones de palabras conocidas (Casa2026, perroverde) o datos personales como cumpleaños y nombres.
Ataque

Fuerza bruta

Prueba todas las combinaciones posibles hasta dar con la correcta. El número de claves es (caracteres posibles)longitud, así que crece muy deprisa al aumentar la longitud o los tipos de carácter.

Ejemplo: 5 letras minúsculas (27 símbolos) dan 275 = 14.348.907 combinaciones; con mayúsculas y minúsculas (54 símbolos) serían 545 = 459.165.024.

Ataque

Diccionario

Prueba palabras de un diccionario, completado con contraseñas filtradas en brechas anteriores. Es más eficaz que la fuerza bruta porque muchos usuarios eligen claves fáciles de recordar.

Defensa: contraseñas complejas y limitar los intentos de acceso, como el PIN de una SIM, que se bloquea y exige el PUK.

¿Dónde se guardan las contraseñas?

GNU/Linux: en /etc/shadow, que no guarda la contraseña sino su hash y datos de caducidad. Solo root puede leerlo. Al iniciar sesión, el sistema calcula el hash de lo que escribimos y lo compara con el almacenado. (/etc/passwd, legible por todos, solo contiene una "x" en el campo de contraseña.)

Windows: en la base de datos SAM (Security Account Manager), protegida por el sistema. Las cuentas se consultan con herramientas como net user.

Caducidad y control de cuentas en Linux

Los campos de /etc/shadow controlan la caducidad; algunos comandos útiles:

passwd usuario          # cambiar contraseña
usermod -L usuario      # bloquear la cuenta (añade "!" en shadow)
usermod -U usuario      # desbloquearla
usermod -e 2027-06-30 usuario   # fecha de caducidad de la cuenta

El módulo PAM (pam_cracklib / pam_pwquality) comprueba la complejidad de las contraseñas al crearlas o cambiarlas con passwd.

Auditoría

John the Ripper

Herramienta que usan los administradores para auditar la fortaleza de las contraseñas de sus propios sistemas. Genera el hash de cada candidato (por fuerza bruta o por diccionario) y lo compara con el hash que se quiere romper: si coincide, ha encontrado la contraseña.

Requiere acceso a los hashes (por ejemplo /etc/shadow, protegido para usuarios normales).

Debe usarse únicamente en sistemas propios o con autorización expresa.

SSO y autenticación multifactor (MFA)

Con Single Sign-On (SSO) el usuario se autentica una vez y accede a varios servicios sin recordar una contraseña distinta para cada uno. Pero concentra el riesgo: si alguien consigue esas credenciales, podría acceder a muchos servicios.

Por eso el SSO debe protegerse con MFA, que combina varios factores (por ejemplo, contraseña y confirmación en el móvil) y refuerza el control de acceso.
